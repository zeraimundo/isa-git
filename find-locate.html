Problema real

Você sabe que o arquivo existe… mas não sabe onde está

Imagine o cenário

Um servidor Linux possui milhares de arquivos espalhados em vários diretórios. Você precisa encontrar:

relatorio_final.pdf

Procurar manualmente seria lento, cansativo e sujeito a erro.

$ cd /
$ ls
bin boot dev etc home lib opt root usr var
# Por onde começar?
Duas ferramentas

find e locate resolvem problemas parecidos, mas de formas diferentes

find

Procura percorrendo os diretórios em tempo real.

É mais poderoso, aceita muitos filtros e pode executar comandos sobre os resultados.

locate

Procura em um banco de dados indexado.

É muito rápido, mas pode não mostrar arquivos criados recentemente se o índice não estiver atualizado.

Ideia central: use find quando precisar de precisão e filtros avançados. Use locate quando quiser velocidade.

O que o find faz?

Ele começa em um ponto da árvore e vai descendo pelos diretórios, testando cada item contra os critérios definidos.

find

Sintaxe básica do comando

$ find [caminho] [opções] [expressão]

1. Caminho

Onde a busca começa. Ex.: ., /home, /var/log.

2. Opções

Ajustam o comportamento. Ex.: profundidade, links, mensagens de erro.

3. Expressão

Define o que procurar. Ex.: nome, tipo, tamanho, data, permissão.

Primeiros exemplos

Buscando a partir de diferentes lugares

$ find .
# procura a partir do diretório atual

$ find /home
# procura a partir de /home

$ find /var/log
# procura dentro dos logs do sistema

O ponto .

No Linux, . representa o diretório atual.

Por isso, find . significa:

“procure daqui para baixo”.

📌 Muito usado em exercícios e scripts
Interativo

Simulador: procure por nome

Digite o nome ou parte do arquivo

Teste exemplos como relatorio.txt, backup.sh, .conf, foto ou log.

Resultado aparecerá aqui...
$ find . -name "relatorio.txt"

$ find . -name "*.sh"

-name x -iname

Maiúsculas e minúsculas importam?

-name

Busca sensível a maiúsculas e minúsculas.

$ find . -name "Relatorio.txt"
./documentos/Relatorio.txt

-iname

Ignora diferenças entre maiúsculas e minúsculas.

$ find . -iname "relatorio.txt"
./documentos/Relatorio.txt
./documentos/relatorio.txt
Tipos de arquivo

Filtrando por arquivos, diretórios e links

fArquivos comuns

$ find . -type f

Mostra arquivos como .txt, .sh, .pdf.

dDiretórios

$ find . -type d

Mostra pastas e subpastas.

lLinks simbólicos

$ find . -type l

Mostra atalhos simbólicos.

Extensões

Encontrando arquivos por extensão

$ find . -name "*.txt"
./documentos/relatorio.txt
./aulas/notas.txt

$ find . -name "*.pdf"
./documentos/apostila.pdf
./downloads/manual.pdf

$ find . -name "*.sh"
./scripts/backup.sh

Atenção às aspas

Use aspas em padrões como "*.txt".

Isso evita que o shell expanda o padrão antes do find executar.

✅ Recomendado: find . -name "*.txt"
Tamanho

Localizando arquivos grandes ou pequenos

Operadores de tamanho

+100M maior que 100 MB

-1M menor que 1 MB

50M exatamente 50 MB, dependendo do arredondamento de blocos

Útil para descobrir o que está ocupando espaço no disco.

$ find . -type f -size +100M
./videos/aula-linux.mp4
./backups/backup-servidor.tar.gz

$ find . -type f -size -1M
./scripts/menu.sh
./documentos/anotacoes.txt
Datas

Encontrando arquivos por tempo de modificação

-1últimas 24h
-7últimos 7 dias
7exatamente 7 dias
+30mais de 30 dias
+365mais de 1 ano
$ find . -type f -mtime -7
# arquivos modificados nos últimos 7 dias

$ find . -type f -mtime +30
# arquivos modificados há mais de 30 dias
Permissões

Procurando por permissões específicas

Exemplo perigoso

777 significa leitura, escrita e execução para dono, grupo e outros.

Nem sempre é erro, mas em servidores pode representar risco.

$ find . -perm 777
./publico/script.sh

$ find . -type f -perm 644
./documentos/relatorio.txt

$ find . -type f -executable
./scripts/backup.sh
Usuário e grupo

Localizando arquivos por dono

$ find /home -user aluno
/home/aluno/documentos/relatorio.txt
/home/aluno/scripts/backup.sh

$ find /var/www -group www-data
/var/www/html/index.html

Por que isso é útil?

Em administração Linux, é comum investigar arquivos pertencentes a um usuário, serviço ou grupo específico.

Exemplos: www-data, mysql, root, aluno.

Critérios combinados

O poder real aparece quando combinamos filtros

$ find . -type f -name "*.log" -size +10M
# arquivos comuns, com extensão .log, maiores que 10 MB

$ find /home -type f -iname "*.pdf" -mtime -30
# PDFs modificados nos últimos 30 dias

$ find /var/log -type f -name "*.log" -user root
# logs pertencentes ao usuário root

Ações com -exec

O find também pode executar comandos

⚠️ Cuidado

O parâmetro -exec permite executar comandos nos arquivos encontrados.

Isso é poderoso, mas comandos como rm podem apagar arquivos em massa.

Antes de apagar, sempre teste imprimindo os resultados.

$ find . -name "*.tmp"
# primeiro confira

$ find . -name "*.tmp" -exec rm {} \;
# {} representa cada arquivo encontrado

$ find . -name "*.sh" -exec chmod +x {} \;
# torna scripts executáveis
Locate

O locate é rápido porque usa um índice

Sistema de arquivos
→
updatedb
→
Banco de dados
→
locate

Analogia: o locate funciona como consultar o índice de um livro. É rápido, mas o índice precisa estar atualizado.

updatedb

Atualizando o banco usado pelo locate

$ locate relatorio.txt
/home/aluno/documentos/relatorio.txt

$ sudo apt update
$ sudo apt install plocate
# instala locate e updatedb no Debian 13

$ sudo updatedb
# atualiza o índice de busca

$ locate backup.sh
/home/aluno/scripts/backup.sh

Quando usar updatedb?

Quando você criou, moveu ou removeu arquivos recentemente e quer que o locate reflita essas mudanças.

No Debian 13: instale o pacote plocate caso os comandos locate e updatedb ainda não existam.

Em muitas distribuições, essa atualização já ocorre automaticamente por agendamento.

Boas práticas

Cuidados importantes em aula e em servidores reais

1. Teste antes

Antes de usar -exec rm, rode o find sem apagar nada.

2. Use aspas

Prefira "*.log", "*.txt" e padrões protegidos por aspas.

3. Redirecione erros

Em buscas no /, use 2>/dev/null para ocultar erros de permissão.

$ find / -name "*.conf" 2>/dev/null
# procura arquivos .conf e oculta mensagens de permissão negada
